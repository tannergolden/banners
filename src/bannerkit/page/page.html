Banners

Blueprint banners that read the profile or repository they sit in. The title, the tagline and the figures ruled along the header's foot come from GitHub, measured every day and redrawn when they move, the way trophies keeps its case. Every image here is drawn by the kit's own Python, from a sample measurement.

      What you are looking at

      Every image on this page is a file the kit drew, shown the way GitHub shows a README image: as an <img>, in a frame the width of a README column. A wide file is 830 px, a desktop column. A narrow file is 360 px, drawn for a phone, and GitHub shows it below px of viewport. The two subjects are samples with made-up numbers, trophies' own octo-dev.

      Where the words come from

      A run reads GitHub over its API with the workflow's own token: the repository's name, description, release, stars, forks, open issues, language and licence, or a person's name, bio, status, followers, repositories, stars earned and contributions. The footer's date is the last commit a person made; a bot's commit or a refresh of the kit never moves it.

      What every file holds to

      No script, no external font, image or stylesheet, no foreignObject. Text is outlined from trophies' Barlow Condensed, now with every Latin-1 and Latin Extended-A letter, so a name reads as its owner wrote it. Colours are emblems' tokens, checked by the kit's lint on every file. Nothing is drawn by the viewer's own font, and no header carries an emoji.

      Still to decide

      Which header, which footer and which print. Which figures a repository and a profile show by default. Whether a profile's status message belongs on the sheet as its note. Whether the refresh commit is authored by the kit's author, as emblems' and trophies' are.
